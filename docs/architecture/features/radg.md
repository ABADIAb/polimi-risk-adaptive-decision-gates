# Feature: Physical RADG

## 1. Architecture Placement
**Phase 6: Physical RADG** | [[Architecture_v5]]

The Physical RADG is the core contribution of Architecture V5. It evaluates the physical feasibility (QoT) of candidate paths generated by the Symbolic Solver. It operates *after* the [[semantic_gate]] has verified intent clarity, focusing entirely on physical risk.

The Physical RADG maps the QoT evaluation results from Phase 5 to a final action space: `{approve, replan}`. The `clarify` action is handled upstream by the Semantic RADG, ensuring a clean separation of concerns.

## 3. How it Works
The decision logic is implemented in `src/core/radg.py` as a deterministic function:
- **`approve`**: If *at least one* candidate path passes QoT validation (i.e., `feasible == True`).
- **`replan`**: If *all* candidate paths fail QoT validation (or if no paths were generated).

The LangGraph node `radg_node.py` executes this decision:
- On **approve**, the graph routes to the [[plan_synthesizer]] to finalize the optimal route.
- On **replan**, the graph triggers a HITL `interrupt()` to notify the operator that physical constraints cannot be met, suggesting they relax GSNR requirements or allow longer routes, before looping back to the PDDL parser.
